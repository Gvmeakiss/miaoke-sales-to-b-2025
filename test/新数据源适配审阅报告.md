# 新数据源适配审阅报告

## 一、新数据源概览

| 类型 | 路径 | 文件列表 |
|------|------|----------|
| **订单** | `input/dingdan` | `24年12月到25年6月订单数据.sql`, `25年7月到25年12月订单数据.sql` |
| **发运单** | `input/fayundan` | `24年12月到25年6月发货数据.sql`, `25年7月到26年1月发货数据.sql` |
| **发票** | `output/fapiao_2025_filtered.pkl` | 已筛选的 2025 年发票（ZA01/ZQ01/ZB02/ZQ07 四类） |

---

## 二、当前代码期望 vs 新数据源

### 1. 订单 (preprocess_oms_full_year.py / match_dms.py)

| 项目 | 当前代码期望 | 新数据源 |
|------|--------------|----------|
| **路径** | `OMS25年1-12月订单及发货数据` | `input/dingdan` |
| **文件名** | `25年1-9月订单数据.sql` + `25年10-12月订单数据.sql` | `24年12月到25年6月订单数据.sql` + `25年7月到25年12月订单数据.sql` |
| **列结构** | 11 列（无 line_amount）或 13 列（含 channel_name2） | **12 列**（含 line_amount，**无** channel_name2） |
| **订单列定义** | COLS_11 / COLS_13 | 需新增 **COLS_12** |

**新订单 SQL 实际列（12 列）：**
```
platform_order_no, main_order_no, sale_order_no, order_type, order_status,
create_time, update_time, channel_name, item_code, line_amount, pay_amount, item_num
```

---

### 2. 发运单 (preprocess_oms_full_year.py / match_dms.py)

| 项目 | 当前代码期望 | 新数据源 |
|------|--------------|----------|
| **路径** | 同订单目录 | `input/fayundan` |
| **文件名** | `25年1-9月发货数据.sql` + `25年10-12月发货数据.sql` | `24年12月到25年6月发货数据.sql` + `25年7月到26年1月发货数据.sql` |
| **列结构** | 7 列或 8 列 | **9 列** |
| **发运单列定义** | COLS_7 / COLS_8 | 需新增 **COLS_9** |

**新发运单 SQL 实际列（9 列）：**
```
business_type, 订单号, external_order_no, 业务时间, 料号, 名称, 已发货数量, document_no, main_order_no
```

前 7 列与 COLS_7 一致，多出 `document_no`、`main_order_no`。匹配逻辑需要 `订单号` 或 `主单号`（DD 开头）+ `料号`，新数据中 `main_order_no` 可对应 `主单号`。

---

### 3. 发票 (preprocess_oms_full_year.py / match_oms.py / match_dms.py)

| 项目 | 当前代码期望 | 新数据源 |
|------|--------------|----------|
| **来源** | Excel `2025-01.XLSX`～`2025-12.XLSX` → 预处理生成 pkl | 直接使用 **fapiao_2025_filtered.pkl** |
| **路径** | `妙可 SAP发票拆分月份` 或 `SAP开票数据` | `output/fapiao_2025_filtered.pkl` |
| **发票类型** | 代码内按中文/代码筛选 | 已由 filter 脚本筛选 ZA01/ZQ01/ZB02/ZQ07 |
| **列结构** | OMS销售单号、物料编码、含税金额/实际金额(ZFN1)、开票数量 等 | **兼容**，已包含上述列 |

**fapiao_2025_filtered.pkl 关键列：**
- 匹配：`OMS销售单号`, `DMS销售单号`, `物料编码`
- 金额：`含税金额`, `实际金额（ZFN1）`
- 数量：`开票数量（基本单位数量）`, `开票数量（销售单位）`
- 分组：`销售组织`

结论：发票结构可直接使用，**无需适配**，只需修改加载路径。

---

## 三、结论与修改建议

### 总体结论

| 数据源 | 兼容性 | 说明 |
|--------|--------|------|
| 订单 | ❌ 不兼容 | 列结构 12 列、文件名、路径均不同 |
| 发运单 | ❌ 不兼容 | 列结构 9 列、文件名、路径均不同 |
| 发票 | ✅ 兼容 | 列结构满足需求，仅需改加载路径 |

### 建议修改清单

1. **preprocess_oms_full_year.py**
   - 数据目录：`OMS25年1-12月订单及发货数据` → `input/dingdan`、`input/fayundan`
   - 订单文件：支持 `24年12月到25年6月订单数据.sql` + `25年7月到25年12月订单数据.sql`
   - 发运单文件：支持 `24年12月到25年6月发货数据.sql` + `25年7月到26年1月发货数据.sql`
   - 订单列：新增 COLS_12，处理 12 列（有 line_amount，无 channel_name2）
   - 发运单列：新增 COLS_9，支持 9 列，将 `main_order_no` 映射为 `主单号`
   - 发票：改为直接加载 `output/fapiao_2025_filtered.pkl`，不再依赖 Excel 预处理

2. **match_dms.py**
   - 若保留“从 SQL 直接读取”：同步调整订单/发运单路径、文件名、COLS_12/COLS_9
   - 若改为依赖预处理结果：只需确保 preprocess 的输出路径正确即可

3. **match_oms.py**
   - 发票来源：从 `2025年全年SAP原始数据.pkl` 改为可配置加载 `output/fapiao_2025_filtered.pkl`
   - 或保持预处理流程，由 preprocess 使用新数据源生成 `2025年全年SAP原始数据.pkl`

4. **sql_to_accounting_excel.py**（如仍需用）
   - 订单/发运单路径改为 `input/dingdan`、`input/fayundan`
   - 文件名需与新数据源一致

## 四、COLS_12 与 COLS_9 定义建议

**COLS_12（订单）：**
```python
COLS_12 = [
    'platform_order_no', 'main_order_no', 'sale_order_no', 'order_type', 'order_status',
    'create_time', 'update_time', 'channel_name', 'item_code', 'line_amount', 'pay_amount', 'item_num'
]
# 合并时补 channel_name2=np.nan，统一为 13 列以便与既有匹配逻辑兼容
```

**COLS_9（发运单）：**
```python
COLS_9 = ['business_type', '订单号', 'external_order_no', '业务时间', '料号', '名称', '已发货数量', 'document_no', 'main_order_no']
# 匹配时：主单号 = main_order_no，若无则用 订单号
```
