# 三单匹配键核对（依据客户确认字段定义）

## 一、字段定义汇总（客户确认）

| 数据源 | 字段 | 业务含义 |
|--------|------|----------|
| **订单 SQL** | platform_order_no | DMS 订单号 |
| | sale_order_no | OMS 子订单号 |
| | main_order_no | OMS 主订单号 |
| **发运单 SQL** | 订单号 | OMS 子订单号 |
| | external_order_no | DMS 订单号 |
| | main_order_no | OMS 主订单号 |

**业务规则**：未拆单时 子订单号=主订单号；拆单时 子订单号≠主订单号。

## 二、DMS 三单匹配键

DMS 全流程使用 **DMS 订单号** 作为统一标识。

| 数据源 | 匹配键字段 | 对应业务含义 | 当前代码 |
|--------|------------|--------------|----------|
| 订单 | platform_order_no + item_code | DMS订单号 + 物料 | ✓ 正确 |
| 发运单 | external_order_no + 料号 | DMS订单号 + 物料 | ✓ 正确 |
| 发票 | DMS销售单号 + 物料编码 | DMS订单号 + 物料 | ✓ 正确 |

**结论**：DMS 匹配键 **DMS订单号 + 物料** 正确，无需修改。

---

## 三、OMS 三单匹配键（关键差异）

发票侧使用的是 **OMS主订单号**（OMS销售单号），而非 OMS 子订单号。

| 数据源 | 应使用字段 | 对应业务含义 | 当前代码实际使用 | 是否一致 |
|--------|------------|--------------|------------------|----------|
| 订单 | main_order_no + item_code | OMS主订单号 + 物料 | sale_order_no + item_code（子订单号） | ❌ 不一致 |
| 发运单 | main_order_no + 料号 | OMS主订单号 + 物料 | 主单号(优先) 或 订单号 + 料号 | ⚠️ 部分一致 |
| 发票 | OMS销售单号 + 物料编码 | OMS主订单号 + 物料 | OMS销售单号 + 物料编码 | ✓ 正确 |

### 3.1 当前 OMS 逻辑与问题

**订单**：当前用 `sale_order_no`（子订单号）。  
- 未拆单：子=主，可与发票匹配 ✓  
- 拆单：子≠主，与发票（主订单号）无法匹配 ✗  

**发运单**：当前逻辑为「主单号优先（DD 开头），否则用订单号」。  
- 主单号 = main_order_no = OMS主订单号 → 与发票一致 ✓  
- 订单号 = OMS子订单号 → 当主单号为空时，与发票不一致 ✗  

**发票**：使用 OMS销售单号（主订单号），符合定义 ✓  

### 3.2 建议的 OMS 匹配键

为与发票（主订单号）对齐，建议 OMS 三单统一使用 **OMS主订单号 + 物料** 作为匹配键：

| 数据源 | 建议匹配键 | 字段 |
|--------|------------|------|
| 订单 | main_order_no + item_code | OMS主订单号 + 物料 |
| 发运单 | main_order_no + 料号 | OMS主订单号 + 物料 |
| 发票 | OMS销售单号 + 物料编码 | OMS主订单号 + 物料 |

**说明**：  
- 未拆单时 main_order_no = sale_order_no，与您原用「子订单号」等价。  
- 拆单时，需按主订单号聚合多个子订单的金额/数量，再与发票匹配，才能正确对账。
