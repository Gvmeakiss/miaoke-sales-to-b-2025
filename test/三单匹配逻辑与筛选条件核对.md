## 三、OMS 三单匹配（match_oms.py）

### 3.1 订单筛选

| 条件 | 逻辑 | 说明 |
|------|------|------|
| order_status | ≠ 'OBSOLETE' | 排除已废弃 |
| order_status | ≠ 'CANCEL' | 排除已取消 |
| order_type | **不限制** | 全量参与，用于计算全量匹配率 |
| create_time | **不限制** | 不按时间过滤 |
| channel | OMS、OMS_WL 均参与 | OMS_WL 视作 OMS 一起参与三单匹配 |

### 3.2 发运单筛选

| 条件 | 逻辑 | 说明 |
|------|------|------|
| 业务时间 | **不限制** | 全量参与匹配 |

### 3.3 发票筛选（在 fapiao pkl 之上再做一层）

| 条件 | 逻辑 | 说明 |
|------|------|------|
| **发票类型** | 若列为代码格式（如 ZA01）：∈ {ZA01, ZB02, ZQ01, ZQ07} | 与 DMS 统一 |
| | 若列为中文：包含「标准发票 2B」「标准退货发票」「取消标准发票 2B」「取消标准退货发票」 | 含标准、退货、取消 |
| **DMS 销售单号** | 必须为空 | 只做 OMS，剔除 DMS 发票 |

**已统一**：OMS、DMS 均保留 ZA01/ZB02/ZQ01/ZQ07，与 fapiao pkl 一致。

### 3.4 发票 → order-item 的构建

| 情况 | 逻辑 |
|------|------|
| 有 OMS 销售单号 | `order-item` = OMS销售单号 + 物料编码 |
| 无 OMS、有 DMS 销售单号 | 通过订单的 external_order_no + item_code 映射到 sale_order_no，再构建 order-item |

### 3.5 匹配键 order-item

| 数据源 | 键规则 |
|--------|--------|
| 订单 | sale_order_no + item_code |
| 发货 | 主单号（若以 DD 开头）或 订单号 + 料号 |
| 发票 | OMS销售单号 + 物料编码（或映射后的 sale_order_no + 物料编码） |

### 3.6 发票金额/数量列

| 用途 | 匹配规则 |
|------|----------|
| 金额 | 列名含「实际金额」或「ZFN1」 |
| 数量 | 列名含「开票数量」或「基本单位」 |

### 3.7 四大类与细分场景（统一规范，参考 refer/difference_analysis.py）

**统一阈值**（OMS、DMS 共用）：
- 数量差 \< 0.02 视为一致
- 金额差 \< 0.02 视为一致
- 尾差\<1：\|订单-发票金额\| \< 1

**四大类及下属细分场景**：

| 大类 | 细分场景 | 说明 |
|------|----------|------|
| **1.完全匹配** | 1.完全匹配 | 订单=发货=发票(数量)、金额一致 |
| **2.数量一致金额有差异** | 2.1 尾差\<1 | 订单=发货=发票(数量)，金额差异在1以内 |
| | 2.2 其他 | 该大类下未计入2.1的所有其他情况 |
| **3.金额一致数量有差异** | 3.金额一致数量有差异 | 数量有差异但金额一致 |
| **4.均有差异** | 4.1 未完全发货（订单数量>收货单数量=开票数量） | 订单数量>收货单数量=开票数量（与 4.4 互斥） |
| | 4.2 未完全开票 | 订单数量 = 发货单数量 \> 开票数量 |
| | 4.3 过量发货 | 订单数量 \< 发货单数量 |
| | 4.4 预制发票 | 订单数量 = 开票数量 \> 发货数量 |
| | 4.5 其他 | 该大类下未计入上述小场景的所有其他可能 |
| **5.有缺失** | 5.缺失发票 / 5.Not test | 缺失发票或关键字段缺失 |

### 3.8 汇总表及明细导出（参考 refer/difference_analysis.py）

**汇总表**（第一个 sheet）列结构：

| 列名 | 说明 |
|------|------|
| 分类 | 四大类及细分场景名称 |
| 记录数 | 该分类的记录条数 |
| 占比 | 占全部数据的百分比 |
| 开票金额 | 该分类的开票金额合计 |
| 发票金额占比 | 占正数发票总额的百分比（存在冲销时） |
| 订单发票金额差异 | 该分类的「订单金额 - 发票金额」合计 |

**各类型明细**：每个分类对应一个独立 sheet，包含该分类的明细数据。

## 四、DMS 三单匹配（match_dms.py）

### 4.1 订单筛选

| 条件 | 逻辑 | 说明 |
|------|------|------|
| channel_name | 含 'DMS'（不区分大小写） | 只保留 DMS 渠道订单 |
| order_status | ≠ 'OBSOLETE' | 排除已废弃（与 OMS 一致） |
| order_status | ≠ 'CANCEL' | 排除已取消（与 OMS 一致） |
| order_type | 不限制 | 全量参与匹配 |
| create_time | 不限制 | 全量参与匹配 |

### 4.2 发货筛选

| 条件 | 逻辑 | 说明 |
|------|------|------|
| external_order_no | 非空 | 只保留有外部订单号的发货 |

⚠️ **无** 业务时间 过滤。

### 4.3 发票筛选

| 条件 | 逻辑 | 说明 |
|------|------|------|
| **发票类型** | 若列为代码：∈ {ZA01, ZB02, ZQ01, ZQ07}；若为中文：同上四类描述 | 与 OMS 统一 |
| **DMS 销售单号** | 非空 | 只做 DMS 发票 |

**已统一**：DMS 与 OMS 一致，保留 ZA01/ZB02/ZQ01/ZQ07。

### 4.4 匹配键

| 数据源 | 键规则 |
|--------|--------|
| 订单 | platform_order_no + item_code |
| 发货 | external_order_no + 料号 |
| 发票 | DMS销售单号 + 物料编码 |

### 4.5 发票金额/数量列

| 用途 | 列名 |
|------|------|
| 金额 | 含税金额 |
| 数量 | 开票数量（销售单位）、开票数量（基本单位数量） |

### 4.6 差异分类与阈值（与 OMS 统一）

**统一阈值**（参考 refer/difference_analysis.py）：
- 数量差 \< 0.02 视为一致（SAP-DMS发货数量）
- 金额差 \< 0.02 视为一致（SAP-DMS订单金额）

| 项目 | 说明 |
|------|------|
| 2.Not test | DMS订单金额 或 DMS发货数量 缺失 |
| 1.1 完全匹配 | \|数量差\| \< 0.02 且 \|金额差\| \< 0.02 |
| 1.2 金额不一致 | \|数量差\| \< 0.02 且 \|金额差\| ≥ 0.02 |
| 1.3 数量不一致 | \|数量差\| ≥ 0.02 且 \|金额差\| \< 0.02 |
| 1.4 均不一致 | \|数量差\| ≥ 0.02 且 \|金额差\| ≥ 0.02 |

## 五、需确认的问题

### 5.1 发票类型范围

| 问题 | 当前状态 | 建议核对 |
